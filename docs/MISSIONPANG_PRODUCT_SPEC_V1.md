## 0. 핵심 제품 정의

**가족 모두가 플레이어로 참여하는 게임형 가족 생활·성장 앱.**

- 현실의 미션: 아이의 공부, 생활습관, 집안일 및 가족 공동 활동
- 기대 가치: 아이의 자기주도성, 좋은 습관, 가족 협력·소통, 성장 기록, 약속한 보상 관리
- 부모: 가족 미션 관리 및 승인도 담당하지만, 부모 자신도 게임 플레이어
- 게임 루프: 미션 수행 → 완료 신청 → 다른 성인 관리자 승인 → 개인 보석 지급 → 보석 수집·조합 → 주간 가족 공동 목표 → 가족 특별 보석·개인 기념 보상·콘텐츠 해금
- 경쟁보다 협력을 우선. 미완료 시 보석 몰수·캐릭터 퇴화·벌칙 금지.
- 부모 및 아이가 각자 **자신의 기기**에서 접속하며, 공동 데이터는 서버 동기화.

### 결정 간 우선순위·충돌 해소

1. **Q11 F → Q12 B:** 일정 자체는 자동 반복 가능하지만, 담당자는 부모가 직접 지정한다. 자동 로테이션은 구현하지 않는다.
2. **Q17 A → Q18 B:** 가족의 승인된 미션 완료 *횟수*는 통계로 보존하되, 주간 목표 달성은 난이도별 *기여 점수* 합계로 판단한다.
3. **Q6 B ↔ Q8-4 E:** 가족 공동 합성은 재료가 소모되지 않는 것으로 확정. **개인 합성**의 소모 규칙만 미확정.
4. **Q10 ↔ Q12:** 아이·성인 모두 자기 완료 신청을 스스로 최종 승인할 수 없다. 승인자는 다른 성인 관리자.
5. **Q13, Q15**는 사용자 요청에 따라 계속 미확정으로 유지한다.

## 2. 미션·승인·보상 기능 계약

### 미션 유형
- 생활습관 / 학습 / 집안일 / 가족 활동
- 1회성, 매일, 선택 요일, N일·N주·N개월 간격, 기간별 목표 횟수
- 반복 미션은 '템플릿'과 '실제 수행 건'을 구분하며 과거 수행·보상 이력 보존
- 담당자는 성인 관리자가 지정. 담당 미정 수행 건은 특정 개인의 미완료율에 포함하지 않는 것을 권장

### 완료·승인 상태
1. `ASSIGNED / IN_PROGRESS` — 수행 전·중
2. `SUBMITTED` — 수행자가 완료 신청, 보석 미지급
3. `APPROVED` — 다른 성인 관리자 승인, 개인 보석 지급·가족 기여 확정
4. `NEEDS_REWORK` — 승인자가 재확인 요청, 보석 미지급 및 재신청 가능
5. `CANCELLED / NOT_COMPLETED` — 별도 보석 차감 없음

- 미션 **제안 승인**과 **미션 완료 승인**은 서로 다른 개념.
- 서버에서 승인자 권한과 '승인자 ≠ 수행자' 검증.
- 동일 수행 건의 보상 지급과 가족 기여 집계는 중복 금지(멱등성).
- 부모 승인 지연을 아이의 미완료나 무단 실패로 취급하지 않는다.
- 보석 지급·기여·알림 이벤트는 감사 가능한 이벤트/거래 기록으로 남긴다.

### 가족 주간 목표
- 한 가족의 **승인된** 미션 수행 건에서 난이도별 기여 점수를 합산.
- '이번 주 누적 기여 점수'와 '총 승인된 미션 완료 횟수'를 **별도** 표기.
- 가벼움/보통/도전 = 1/2/3점, 주간 30점은 설명용 후보이지 확정값 아님.
- 구성원별 기여 기록은 보여주되 동일 기여 강요/승패 비교/과도한 경쟁 금지.
- 목표 달성 시 가족 보석함에 특별 보석, 참여자 개인 기념 보상, 콘텐츠 해금.
- 가족 특별 보석을 만드는 공동 합성에서 **개인 보석은 소모되지 않는다**.
- 각 가족 구성원의 기여와 이벤트 중복 달성 보상을 원장으로 관리.
- 주간 경계·지난주 미션 늦은 승인·반복 미션 상한은 코드에 고정하지 말고 명시적 설정으로 격리.

### 보석 경제
- 보석 종류: 실존 보석 + 판타지 보석 혼합, 구체 디자인 시안으로 결정.
- 희귀도: 일반/희귀/전설 3단계. 희귀도와 도감 최초 발견 여부는 별도 필드.
- 미션별 고정 보상은 사전 표시, 특별 발견은 별도 이벤트·안전한 조건 기반.
- 미션 난이도/노력과 개인 보상은 연결하되 학습/집안일의 우열로 보상 차등을 고정하지 말 것.
- 개인 보석: 수집·도감·개인 조합 후보(소모/비소모/중복 소모는 시제품 비교).
- 가족 보석: 공동 소유 및 콘텐츠 해금, 개인 소유권과 분리.
- 무한 반복 합성으로 특별 보상을 무제한 복제하지 않도록 중복·도감 정책 명시.

## 3. 인증·동기화·알림

- 가족 구성원: 개별 기기에서 자신만의 플레이어 계정; 성인 관리자는 게임 플레이 권한과 별도로 관리·승인 권한.
- 최초 기기 연결: 부모 승인에 기반한 **일회용 단기 유효 QR/연결 코드**. 비밀번호나 장기 세션 토큰을 QR에 담지 말 것.
- 이후 자동 로그인 + 기기 잠금 보호, 분실/기기 변경 시 연결 철회 가능하도록 설계.
- **어린이 Google 로그인은 정책 검증 완료 전 구현 전제로 삼지 않는다.** Google 로그인 없이 가능한 대체 인증을 우선 확보하고 대상 연령, Google Play Families, Google API Services User Data, Family Link 관련 최신 공식 정책을 검증한다.
- 알림: (1) 완료 승인 요청 → 승인 가능한 다른 성인 관리자, (2) 보석 지급 확정 → 수행자, (3) 가족 공동 목표 달성 → 가족 구성원. 이벤트 확정 후 즉시 발송 시도.
- 새 미션 배정/마감 알림은 요청되지 않은 초기 범위이므로 임의 추가 금지.
- 푸시 전송에 실패해도 승인·지급 자체는 롤백하지 않음. 앱 내 알림함과 서버 상태 조회 지원.
- **오프라인:** 이전에 저장된 정보 열람만 허용. 완료 신청, 승인, 보석 합성 등 서버 상태 변경은 온라인 연결이 필요. 오프라인 자동 쓰기 대기열로 Q16 정책을 깨지 않도록 주의.
- 서버가 권한·보석 잔액·승인·가족 성취의 최종 기준.

## 4. UI/UX — 개발 최우선 요구사항

### 목표
- **프리미엄 캐주얼 모바일 게임 같은 완성도**: 생생한 입체 보석, 깊이감 있는 배경, 자연스러운 그림자·광원, 고급 재질, 반짝임·파티클, 부드러운 터치 피드백.
- **권장 제작 방식: 2.5D 에셋 중심 + 필요한 곳만 실제 3D**. 모든 화면을 WebGL로 구현할 필요 없음.
- 게임과 관리 UI가 동일한 디자인 언어를 공유하되, **관리 화면의 정보 위계·가독성이 화려한 장식보다 우선**.
- AI 생성 이미지는 콘셉트 탐색·원본 에셋 후보로 활용, 화면 전체를 통이미지로 붙이지 말 것. 원본 인터랙티브 UI, 텍스트·버튼·상태는 코드로 렌더링.
- 부모도 게임 플레이어이므로 부모 홈에서 자신의 보석 게임과 관리자 미션 기능 **모두 접근**해야 함.

### Q13 메인 화면 비교군 (모두 미확정)
- **A 게임 중심형:** 보석 세계 우선, 미션 별도 진입.
- **B 미션 중심형:** 오늘 할 일 우선, 게임 별도 진입.
- **C 통합형:** 보석 현황 + 미션 현황 한 화면.
- **D 게임 속 퀘스트형:** 게임 세계의 탐험 요소에서 미션으로 진입.

하나의 앱에서 UI 전환 기능을 제공하고, **아이·부모 각각 동일한 실험 데이터**로 네 화면을 비교. 네 가지 앱을 중복 개발하지 말고 공통 상태·도메인 로직을 공유할 것. 4종 중 특정안을 임의 확정하지 말 것.
